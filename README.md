# Ancient Warfare Structures Encyclopedia

A community catalogue of structures and structure packs for the Ancient Warfare 2 Minecraft mod. Browse builds, discover their authors, and find packs to try in your world.

**[Visit the website](https://ancient-warfare.legends-of-gramdatis.com/)**

## Features

- Search structures, view their metadata, and download available templates.
- Browse structure packs and their contributors.
- Explore an author directory with structure counts and pack contributions.
- Discover random structures, including illustrated recommendations.
- Use the catalogue on desktop and mobile devices.

The website uses HTML, CSS, and JavaScript, with a JSON catalogue generated by a Python script. It has no application backend or build step. The browser caches the catalogue in IndexedDB and checks its version on subsequent visits.

## Getting started

You need Git, Python 3, and a modern web browser. Node.js 18 or newer is needed only to run the tests.

```bash
git clone https://github.com/TheOddlySeagull/ancient-warfare-encyclopedia-website.git
cd ancient-warfare-encyclopedia-website
python3 -m http.server 8000 --bind 127.0.0.1
```

Open [http://127.0.0.1:8000](http://127.0.0.1:8000). On Windows, use `py` instead of `python3` if needed. Serve the files over HTTP rather than opening `index.html` directly, because the site uses JavaScript modules and fetches JSON files.

Structure templates, structure illustrations, author galleries, and downloadable ZIP archives are excluded from Git. A fresh clone can display the included catalogue, but corresponding images and downloads require those assets to be added separately.

## Project structure

| Path | Purpose |
| --- | --- |
| `index.html` | Entry point; redirects to the structure catalogue. |
| `html/` | Catalogue, structure, pack, author, and information pages. |
| `css/` | Page styles and shared mobile layouts. |
| `js/` | Search, page rendering, catalogue caching, and image loading. |
| `json/` | Generated catalogue, version information, and author/pack metadata. |
| `descriptions.json` | Structure descriptions maintained separately from the generated catalogue. |
| `img/` | Site artwork, structure illustrations, and author images. |
| `structure_data_converter.py` | Converts structure templates into catalogue data and can generate pack archives. |
| `tests/` | Automated tests for catalogue loading, author counts, and image discovery. |

The converter also uses a local `structures/` directory for source templates and a `downloads/` directory for generated ZIP archives.

## Maintaining the catalogue

### Structures and packs

The converter reads `.aws` templates and generates the catalogue in `json/structures.json` or individual records under `json/structures_jsons/`. Its options are available from the repository root:

```bash
python3 structure_data_converter.py --help
```

Run conversions against a complete local copy of the structure assets, and review generated changes before publishing. The converter currently derives pack names from the template's immediate parent directory, so nested folder layouts need particular attention.

Keep the catalogue's `disclamer.version` and `json/structures_version.json`'s `version` consistent when updating the main catalogue; the browser uses these values to refresh its cache. The `disclamer` spelling is part of the existing data format.

### Structure images

Upload a PNG to `img/structures/` with the same basename as its template:

```text
MyStructure.aws → img/structures/MyStructure.png
```

Names are case-sensitive. Match the template filename, which may differ from the internal or displayed structure name. Adding an image to an already catalogued structure does **not** require a JSON update or version bump. Missing images fall back to the AW2 logo.

Illustrated random recommendations check a limited sample of candidates to avoid scanning every image. Newly uploaded artwork is eligible even when the cached catalogue still contains a placeholder icon. Normal browser and server caching still applies.

### Descriptions and author information

Edit `descriptions.json` for structure descriptions; its keys match the internal structure names. Descriptions are incorporated when regenerating catalogue data. Author and pack information is stored under `json/authors/` and `json/packages/`.

Author galleries use `json/author-galleries.json`. The converter refreshes this index from `img/authors/gallery/<author>/*.png` during conversion or archive generation, so run it where the gallery assets are present.

## Testing

Run the test suite from the repository root:

```bash
node --test
```

For layout changes, also check desktop and mobile views, navigation, search, pagination, and structure/author/pack pages. Useful viewport widths are 320, 390, 768, and 1280 CSS pixels.

## Deployment

Serve the repository root with a static HTTP(S) server, such as Nginx, configured to serve JavaScript modules with the correct MIME type. Include the required catalogue and asset files. No Node.js or Python process is needed to serve the deployed site.
