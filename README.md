# Ancient Warfare Encyclopedia

Welcome to the Ancient Warfare Encyclopedia project! This repository houses the codebase for our self-hosted website dedicated to cataloging structures and structure packs from the Ancient Warfare Minecraft mod community. Our goal is to provide a comprehensive resource for players, builders, and modders alike, facilitating easy access to a vast array of structures.

## Project files

### Jsons

#### descriptions.json

This file contains the descriptions for all the structures. It is used to populate the website with the relevant information. It works as a dictionary, with the structure name as the key and the description as the value. The names are case-sensitive and must match the structure names in the structure packs.

#### structures.json

This file contains the structure data. It is used to populate the website with the relevant information. It works as a dictionary, with the structure name as the key and the structure data as the value. Its architecture mirrors the way the .aws structure files are organized.
This json is generated by script, and is not meant to be edited manually.

#### structures_version.json

This file contains the version of the website's structure database. It is used to check if the user's local database is up to date with the website's database. The file is updated every time the website's database is updated.

### python scripts

#### structure_data_converter.py

This script is used to convert the .aws structure files into the structures.json file. It is meant to be run every time a new structure pack is added to the website, or when a structure is updated or removed from the website. The script will generate the structures.json file, which is used to populate the website with the relevant information.

## Static hosting compatibility

Serve the repository over HTTP(S) with JavaScript module MIME types. Catalogue
pages fetch `json/structures.json` through a shared loader; they do not require a
previous Home visit or browser localStorage capacity. IndexedDB caches the full
catalogue; repeat visits check the small version file and reuse it when unchanged.
If browser storage is blocked, the pages fall back to downloading the catalogue.
Illustrated random recommendations use catalogue artwork and retry missing images,
so the host does not need to expose directory listings.

Author galleries use `json/author-galleries.json`. The structure converter refreshes
this index from `img/authors/gallery/<author>/*.png` whenever it runs a conversion
or ZIP generation. Run it on the host containing the gallery assets when adding or
removing gallery pictures; the checked-in index covers the existing gallery.

Generated image paths and downloads follow the current site location. Existing
catalogues containing image URLs for the original domain remain supported.

Run the compatibility regression tests with Node.js 18 or newer:

```sh
node --test tests/catalogue.test.mjs
```

## Phone layout

A shared `css/mobile.css` applies up to 800 CSS pixels across the catalogue,
structure, pack, author, About and Contact pages. It retains the desktop styles
above that breakpoint. The phone navigation uses native HTML details/summary,
so it works before the catalogue loads and without JavaScript.

Phones start with five results per page (desktop: twenty). All existing page-size
choices remain available. Paging on a phone returns to the top of the results;
random discoveries follow the catalogue instead of squeezing it into a sidebar.
Detail section tabs scroll horizontally within their own strip. Author cards and
gallery images fit the viewport. Inputs use a 16px font to avoid iOS focus zoom.

For visual regression checks, use 320, 390, 768 and 1280 CSS-pixel viewports. Check
menu expansion, search + Enter, page size, next/previous page, structure details,
pack lists/details, author pagination/gallery, About and Contact. Verify no page
horizontal overflow, while detail-tab strips remain horizontally scrollable. Also
check keyboard focus and the skip-to-content link. Real-device Safari and Android
touch/keyboard testing remains useful in addition to desktop browser viewport QA.
